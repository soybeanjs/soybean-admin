# soybean-admin v3.0 实现方案

> 基于 ubean + vite-plus + Vean（`@vean/ui`，研发仓库 soybean-ui）的全栈重构方案
>
> 状态：草案（供评审）
> 基线：soybean-admin v2.x（main = 脚手架内核，example = 全功能演示）
> 参考实现：soybean-unify（简约全栈参考）、ubean examples/ubean-test（全栈骨架参考）
> 会话前置阅读（重构前必读）：§3.3 ubean 文件式约定速查、§11.1 关键参考路径、§11.2 本地已装 AI skills
> 版本锚点（2026-10 校）：ubean 0.6.0 · Vean（`@vean/*`）0.50.0 · `@soybeanjs/fetch` 0.1.0 · `@soybeanjs/cli` 1.8.4 · Node >= 22 / pnpm 11.24.0

---

## 1. 背景与目标

soybean-admin v2.x 是纯前端 SPA 模板：Vue 3 + Vite + Naive UI + Pinia + UnoCSS + elegant-router，后端能力完全依赖 Apifox 在线 mock 或用户自备服务。v3.0 的目标：

1. **整体技术栈升级为全栈框架**：以 [ubean](https://github.com/soybeanjs/ubean)（v0.6.0，Vue 全栈框架，Hono 内核）为基座，构建工具链切换为 vite-plus（`vp`），UI 层切换为 [VeanUI](https://veanui.com)（`@vean/ui` + `@vean/aria`）。
2. **能力对齐**：完整实现 v2.x（main + example）的全部能力，不丢"隐形能力"（见 §5.9）。
3. **简约优先**：以 soybean-unify 的简约实现为参考范式——单一契约源（`src/schema/` Valibot）、OpenAPI 类型化客户端、菜单驱动路由/页签/标题的一元数据模型、零自研布局、单包平铺工程结构。
4. **架子 + 样式适配**：用 Vean（`@vean/ui`，研发仓库仍名 soybean-ui）搭好完整架子（布局/导航/页签/主题）；第三方 UI 库（naive-ui / element-plus / ant-design-vue）的**样式适配器**（让第三方组件对齐 Vean 的颜色、圆角等设计 token）在独立仓库开发，使 v2 各发行版平滑过渡到 v3。
5. **双版本交付**：
   - `main` 分支：**全栈版**（ubean 完整能力：文件路由 API + DB + 鉴权 + OpenAPI 类型共享）；
   - `lite` 分支（新分支承载）：**前端版**（仅 `@ubean/vue` 客户端内核 + 自定义后端，任意语言后端可接入）。

### 非目标

- 不实现 v2.x 从未存在过的能力（锁屏、cropper、ripple 等不在 example 基线内，不列入）。
- v3.0 首版不做 SSR/SSG（admin 面板模式官方推荐 `mode: 'fullstack' + ssr: false`）。
- 不做 naive-ui 等旧版组件级 1:1 转发适配（原因见 §7.1），适配器只做样式 token 对齐；适配器实现不进本仓库（§7.2）。

## 3. 仓库与工程结构

### 3.1 项目结构（main 分支 = 全栈版，单包平铺）

v3 不再使用 monorepo：应用直接落在仓库根目录（等价于把 v2 设想中 `apps/admin/` 的内容平铺），全栈应用的天然属性（前端 + API + 数据库同仓同进程）使 workspace 分层失去意义。

```
soybean-admin/
├── ubean.config.ts               # defineConfig: mode/preset/i18n/ui/icon/pinia/devtools/routing
├── vite.config.ts                # import { defineConfig } from 'vite-plus'; plugins: [ubeanPlugin()]
├── .env / .env.prod              # 精简后的 env 变量（见 §5.10）
├── package.json                  # 单包：scripts 用 vp + soy（@soybeanjs/cli）
├── src/
│   ├── pages/                    # 文件式页面路由（替代 v2 src/views）
│   │   ├── (builtin)/            #   login / 403 / 404 / 500 / iframe-page
│   │   ├── home/                 #   dashboard
│   │   ├── manage/               #   user / role / menu / permission / dict ...
│   │   ├── function/             #   功能演示（tab / multi-tab / request / access-control ...）
│   │   ├── multi-menu/           #   多级菜单演示
│   │   ├── plugin/               #   插件演示（editor / excel / pdf / charts ...）
│   │   └── about/
│   ├── routes/                   # API 路由（替代 Apifox mock）
│   │   └── api/
│   │       ├── auth/             #   login / refresh / logout / user-info
│   │       ├── menu/             #   public / user / exist-path
│   │       └── user/ role/ permission/ org/ dict/ ...
│   ├── schema/                   # 前后端共享 Valibot schema + DTO 类型（原 unify packages/schema 下沉至此）
│   ├── layouts/                  # default.vue（= SAppShell 壳）/ blank.vue
│   ├── middleware/               # 服务端鉴权中间件（01.auth.ts）
│   ├── services/                 # 服务端业务层（每资源 *.service.ts）
│   ├── db/                       # Drizzle schema + 迁移 + seed
│   ├── crons/                    # defineScheduled 定时任务（字典缓存刷新等，ubean 约定目录）
│   ├── locales/                  # zh.json / en.json（locale 文件名 = code，直接作 URL 前缀）
│   ├── components/               # 全局小组件
│   ├── composables/              # useTableOperate / useAuth / useCaptcha ...
│   ├── constants/                # 挂载点 ID、正则、i18n key 映射
│   ├── directives/               # v-auth（按钮级权限）等
│   ├── shared/                   # storage / table / request 适配
│   ├── store/                    # pinia: app / auth / menu / route / tab / theme
│   ├── styles/                   # 全局 css（走 @vean/unocss）
│   ├── theme/                    # 主题预设 JSON（shadcn-theme 兼容）
│   ├── request/                  # typed client（client.ts / internal.ts）
│   ├── typings/                  # 环境/全局类型补充
│   ├── server.ts                 # defineServer（全局 hooks）
│   ├── app.ts                    # defineApp（router.setup 守卫、appRoot）
│   └── app.vue                   # appRoot 包装：SConfigProvider + Provider 挂载
├── scripts/                      # 辅助脚本：openapi/seed/remove-i18n（dev/build 由 vp + ubean CLI 承担）
├── docs/                         # v3.md（本文档）等
└── .github/workflows/            # lint + typecheck + build + release
```

要点：

- **删除 v2 的 `packages/` 私有包体系**（`@sa/axios`、`@sa/materials`、`@sa/hooks`、`@sa/color`、`@sa/scripts`、`@sa/uno-preset`、`@sa/alova`、`@sa/ofetch`）与根 `pnpm-workspace.yaml`：其职责分别由 `@soybeanjs/fetch`、soybean-ui、`@soybeanjs/utils`、`@vean/theme`、`@soybeanjs/cli`、`vp` 承担，全部以已发布 npm 包消费，仓库内不再维护本地包。
- **schema 下沉 `src/schema/`**：全栈应用前后端同进程、同 tsconfig，Valibot schema 直接以相对路径 import（`@/schema/auth`），无需 workspace 包；DTO 类型即 schema 推导类型，单一契约源不变。
- **第三方 UI 样式适配不放本仓库**：由独立仓库开发（见 §7.2），本项目只保留对接约定。
- **mock 服务退役**：`src/service/api/*` 手写 API 层与 Apifox mock 全部删除，接口由 `src/routes/api/**` 真实实现，dev 即跑真后端（同进程，Vite middlewareMode + Hono）。
- **v2 `src/views` → `src/pages`**：文件约定基本同构（`[id].vue` 动态段、`(group)` 路由组、`_builtin` → `(builtin)`），迁移以目录重命名 + meta 改写为主。
- 路径别名统一 `@/*` → `./src/*`（由 `vite.config.ts` 的 `resolve.tsconfigPaths` 透传 tsconfig `paths`；**ubean 无内置别名约定**，官方样例（`ubean/examples/*`、`ubean/apps/docs`）统一用 `@/*`），`.ubean/*` 走 `~ubean/*`。
- **新增的 ubean 约定目录/文件**（不在上树单列）：`.ubean/`（codegen 产物，入 `.gitignore`）、`src/crons/`（定时任务）、`src/routes/api/**` 内的 `export const actions`（Server Actions）。
- **路由级弹窗用并行路由**：`src/pages/<parent>/@detail/index.vue` + 父页 `<SlotView name="detail" />`；**不要**用 Nuxt 的拦截路由 `(.)`/`(..)`（ubean 扫描器遇会直接抛错，见 §3.3）。
- **所有页面/客户端代码新增/重构后需注意导入源**：定义/组合 API 从 `ubean/client`，服务端从 `ubean/server`（§3.3）。

### 3.3 ubean 文件式约定速查（重构落地依据）

以下为 ubean 0.6.0 的实测行为（源：`ubean/AGENTS.md`，含 23 条注意事项），v3 实现必须按此书写，勿沿用 Nuxt/其他框架的直觉。

**页面路由（`src/pages/`）**

- `definePage` 合法字段仅：`name` / `path` / `layout`（`string | string[] | false`）/ `reuse` / `meta` / `requiresAuth` / `cache` / `head` / `ssr` / `transition`。**没有顶层 `title`**——标题只能走 `meta`（与 §5.3 的菜单 `i18nKey` 一元模型一致）。
- `cache: true` 会自动把路由名写成组件 `name`；手动控制用 `useCacheViews()` / `enablePageCache` / `disablePageCache` / `excludePageCache` / `invalidatePageCache`。
- 动态段 matcher：文件名 `[id=numeric].vue` + `defineMatcher`；客户端需 `router.beforeEach(createMatcherGuard())`，否则 matcher 不生效。
- **拦截路由 `(.)` / `(..)` 刻意不实现**：页面扫描器遇到会直接抛错。路由级弹窗用**并行路由** `src/pages/<parent>/@detail/index.vue` + 页面内 `<SlotView name="detail" />`。
- 特殊页面固定名：`pages/404.vue`、`loading.vue`、`error.vue`。
- appRoot 优先级：`defineApp({ appRoot })` > `src/app.vue` > `src/App.vue`。
- 其他约定目录：`src/crons/`（`defineScheduled`）、Server Actions（页面/路由文件 `export const actions`）。
- **UnoCSS 必须显式引入**：客户端入口（`src/app.ts`）要写 `import 'uno.css'`，ubean **不会**自动注入原子类。漏掉时 dev 看着正常（Vite 按需注入），但 `vp build` 产物 CSS 只剩应用自带的那几行（实测 49 B），`presetUi` 的所有工具类都不打包。
- **`@vean/ui/styles.css` 也必须显式引入**（`src/app.ts` 里与 `uno.css` 并列）。`ubean.config.ts` 的 `ui: true` 本意是经 module registry 注入它，但**注入只在 `ubean dev` CLI 路径生效**：`prepareBuild()` 先把 `client-entry.mjs` 写盘（`packages/builder/src/production.ts:197`），**之后**才 `resolveModules()`（`packages/builder/src/vite/build-app.ts:185`）→ 构建路径的落盘入口里没有这条 css import。实测 `vp build` / `ubean build` 都会丢组件样式（产物 CSS 4.21 kB vs 应然 192 kB，`bg-popover` / `data-vean-*` 全无）。显式 import 与 registry 注入是同一模块说明符，Vite 去重，两条路径同时存在不会重复。
- `uno.config.ts` **不要扫 `@vean/ui` 的 dist**，且必须 `content.pipeline.exclude: [/node_modules/]`。组件样式已预构建在 `@vean/ui/styles.css`，但 UnoCSS 默认会扫依赖目录，把 `@vean/ui/dist` 里每个候选类名重新生成为全局规则 —— 实测产物 CSS **177.66 kB / gzip 23.32 kB**，加 `exclude` 后降到 **4.21 kB / gzip 1.15 kB**（那 ~173 kB 全是重复）。`content.pipeline.include` 里仍需保留 `.js`/`.ts`（UnoCSS 始终用该列表过滤候选文件，自带默认值是 `[/\.vue$/]`）。
- `presetUi({ resetCSS: false, globalCSS: false, uiCSS: false })`：三者的默认值本就是 `false`；reset / global / ui 组件样式都改由 `@vean/ui/styles.css` 承担，preset 只负责按需生成应用用到的原子类与 theme 变量。
- `@soybeanjs/unocss-preset` 只提供 shortcuts（`flex-center` / `flex-c` / `flex-1-hidden` …），需与 `presetUi()` 同时装；`presetUi()` 自身已返回整条栈（wind3 / animations / scrollbar / webFonts），**不必**再手动加 `presetWind3`。

**API 路由（`src/routes/api/`）**

- **void 风格命名导出**：`export const GET = ...` / `POST` / `PUT` / `PATCH` / `DELETE`，**没有** `.get.ts` 后缀式文件名约定。
- 链路：`defineHandler(defineHandlerMeta, describeRoute, validator('json', schema), handler)`。

**类型 codegen（`.ubean/`，由 `ubean prepare` / dev / build 生成）**

`routes.d.ts`、`pages.d.ts`、`i18n.d.ts`、`auto-imports.d.ts`、`components.d.ts`、`typed-router.d.ts`、`openapi.d.ts`、`virtual-components.d.ts`、`codegen.manifest.json`。实物参照 `ubean/examples/ubean-test/.ubean/`（`openapi.d.ts` 19.8K、`routes.d.ts` 5.8K）。`openapi.d.ts` 同时由 dev（运行中 server 拉 `/_openapi.json`）与 build（`packages/builder/src/vite/openapi-step.ts`）两条路径生成。

**内置端点与虚拟模块**

- 内置：`/_health`、`/_openapi.json`、`/_scalar`、`/_iconify`、`/_devtools`、`POST /__actions`、`POST /__server-component`。
- 虚拟模块：`ubean:pages`、`ubean:routes`、`ubean:meta`、`ubean:app-config`、`ubean:locales`、`virtual:ubean-pages`、`virtual:ubean-islands-registry`。

**环境变量 `defineEnv()`**（`ubean/packages/shared/src/env.ts:124`）

- 形态：`defineEnv({ server, public, mode: 'warn' | 'throw' })`；条目用构造函数 `String` / `Number` / `Boolean` 声明，配 `default` / `required`。
- 限制：只有带**同步** `safeParse` 的 schema 才能用（异步校验器不可用）。
- **`defineEnv()` 只读 `process.env`，不读 `import.meta.env`** → 它实际是**服务端专用**：浏览器无 `process`，`public` 段只会拿到 `default`。客户端变量必须另走 `import.meta.env.VITE_*`（见 §5.10，本仓库拆 `src/env.ts` + `src/env.server.ts`，两者不得共用同名变量）。

**导入路径与构建（体积/消歧陷阱）**

- **客户端代码优先从 `ubean/client` 导入**（主入口 `ubean` 已 isomorphic、导入不会报错，但它是聚合 barrel：shared/seo/pages/markdown + Vue 内核 + islands + logger）。实测一个 `import { defineMatcher } from 'ubean'` 就让示例入口 chunk 从 **45.2 kB gzip 涨到 111.9 kB**（+148%），改 `'ubean/client'` 后回到 +1.5%。两道保险：`pnpm analyze:check`（只看体积）+ `packages/cli/test/example-imports.test.ts`（断言客户端图文件不从主入口导入）。→ v3 需保留同等 CI 闸门。
- `createUbeanApp` 消歧：服务端侧返回 Hono `UbeanApp`；客户端侧是 `createUbeanClientApp`。
- i18n 导入源：`useI18n` **直接从 `vue-i18n` 导入**，`setLocale` 从 `ubean/client`。
- **locale key 必须与 `@vean/aria/locale` 的注册 key 一致，否则组件内置文案静默变英文**。`@vean/aria` 出厂只注册 `en` 与 `zh-CN`（`dist/locale/locales.js`），未知 key **不报错、不告警**，直接回落 `en`：实测 `resolveLocaleRegistry('zh').key === 'en'`、`resolveLocale('zh').table.emptyTitle === 'No data'`。所以 locale 目录用裸码 `zh`/`en`（路径 `/en/...`）时，必须补注册：`registerLocale({ ...zhCN, key: 'zh' })`（`zhCN` 从 `@vean/aria/locale/zh-CN` 默认导入，`registerLocale` 从 `@vean/aria/locale`，`@vean/ui` **不**转出它）。注意 ubean 的 locale 扫描 glob 覆盖 `.ts`（`**/{json,json5,yaml,yml,js,mjs,cjs,ts,mts,cts}`），**补注册文件别放 `src/locales/`**（会被当成一个 locale 收录）。
- 第三方 API 不经 ubean 透传：vue / vue-router / vue-i18n 均直源导入。
- dev 下 SSR 图存在两份模块实例：跨实例状态需挂 `server` 或 `globalThis`。
- 页面元数据序列化白名单：修改 `ScannedPage` 字段必须同步 `serializePagesForEntry()`，由 `packages/builder/test/page-metadata.test.ts` 锁定。
- worker 目标不要把 `ubean/build` 从运行时路由 import（Node 上只是体积浪费，worker 上**构建期直接失败**）。
- 服务端符号只在 `ubean/server`（`defineHandler`/`useDatabase`/`validator`）、构建期符号只在 `ubean/build`；客户端代码从 `ubean/server` 导入会触发 Vite 在浏览器环境预构建 Hono/`node:*`。
- 宏白名单：`macros.ts` 的 `MACRO_NAMES` **只有 `definePage`**；`defineHandlerMeta`/`defineMiddleware` 会被 build strip 导致运行时语法错误。
- dev 请求路由保留命名空间：DevTools 挂载点（`/__devtools`、`/__devtools-assets/`、`/__devtools-client-imports.js`、`/_devtools/**`）需**裸字符串前缀**匹配；框架内置 HTML 页由 `isFrameworkHtmlPage()` 判定跳过 HTML transform。
- peer 变体漂移：catalog `typescript: npm:typescript-native-bridge@latest` 会漂出两份 `vite-plus-core`（`Plugin` 类型身份不一致）；`env-runner` 必须留在 `packages/cli`，不得成为 `@ubean/build` 依赖。
- 虚拟模块前缀用 `virtual:ubean-`（`#ubean-` 会因 URL hash 导致 404）。
- 裸 `vite dev | build | preview` ≡ `ubean dev | build | preview`（ADR-0012：`ubeanPlugin()` 注册 `client` / `ubean` 两个环境 + `builder.buildApp`）；`vite build` **忽略** `--outDir`。
- 工具链要求：**Node >= 22、pnpm 11.24.0**（ubean 根 monorepo `packageManager` 锁定值）；catalog 中 `vite` 钉为 `npm:@voidzero-dev/vite-plus-core@1.0.0`，`vite-plus: 1.0.0`。

### 5.2 布局架子（layouts/default.vue）

```vue
<script setup lang="ts">
import { SAppShell } from '@vean/ui';

const active = ref('');
// items：菜单树（AppShellMenuItem[]，唯一数据入口；面包屑/高亮路径由 shell 派生）
</script>
<template>
  <SAppShell
    v-model="active"
    v-model:tab-value="tabStore.activeTab"
    mode="dual-vertical"
    :items="menuStore.items"
    :tabs="tabStore.tabs"
    expand-strategy="keep"
    @tab-click="tabStore.switchTab"
    @tab-close="tabStore.removeTab"
  >
    <template #logo><AppLogo /></template>
    <template #headerStart>
      <!-- 折叠触发按钮位置由 shell 按一级菜单位置决定，无需手摆 -->
    </template>

    <template #headerEnd>

    </template>
    <template #default><RouterView /></template>
    <template #footer v-if="footerVisible"><LayoutFooter /></template>
  </SAppShell>

```

要点：

- `mode` 承接 v2 全部 6 种布局：`sidebar`（原 vertical / vertical-mix 的侧栏形态）、`top`（原 horizontal）、`dual-vertical`（原 vertical-mix）、`vertical-horizontal`（原 top-hybrid-sidebar-first）、`horizontal-vertical`（原 top-hybrid-header-first）、`horizontal-dual-vertical`（原 vertical-hybrid-header-first）。模式名描述**菜单形态**而非方向：一级菜单垂直 = 全高侧栏，一级水平 = 顶栏；`orientation` 等布局朝向由 shell 从 mode **派生**（相对旧 `SLayout` 直填 props 是反转的），应用层不再手写。
- **一棵菜单树喂所有渲染器**：`items: AppShellMenuItem[]` 是唯一菜单数据入口，sidebar/top 渲染 `STreeMenu`/`STreeNav`，4 种 split 模式渲染 `SSplitNav`，无需按模式切换组件。
- `breadcrumbs` 默认由 `items` + 激活值**自动派生**（原 menu store 派生逻辑内化），传入才覆盖；`expandStrategy: 'selected' | 'keep'` 控制折叠后展开策略（top 模式无此项；`menuProps.tree/split` 优先级更高）。
- 品牌/标题仅经 `#logo`/`#title` 插槽注入，`logoPlacement: 'auto' | 'sidebar' | 'sidebar-bottom' | 'header'` 控制落位（`sidebar-bottom` 仅 sidebar/dual-vertical 生效）；折叠触发按钮位置跟随一级菜单位置，由 shell 统一安排。
- 移动端恒以 `sidebar` 骨架渲染**全量菜单树抽屉**（767.9px 断点；props 保留宿主传值），`v-model:mobileOpen` 受控。
- 主题/布局配置映射：theme store → `layoutProps` 转发内部 `SLayout`（shell 自己持有 open/orientation/sidebarVisible/isMobile/pxToRem，应用层只喂配置面）；样式三层 `ui` / `layoutUi` / `menuUi`（tree/split/treeNav）。
- 与路由无关：纯数据入（items/tabs/breadcrumbs）+ 事件出（`update:open` / `update:mobileOpen` / `update:modelValue` / `select` / `open` / `update:tabValue` / `update:tabs` / `tabClick` / `tabClose`），路由联动留在 route/menu store。

v2 layout.mode → SAppShell mode 映射表：

| v2 layout.mode               | SAppShell `mode`           | 渲染器                  |
| ---------------------------- | -------------------------- | ----------------------- |
| vertical                     | `sidebar`                  | `STreeMenu`（单栏）     |
| vertical-mix                 | `dual-vertical`            | `SSplitNav`（双栏）     |
| horizontal                   | `top`                      | `STreeNav`（横排）      |
| top-hybrid-sidebar-first     | `vertical-horizontal`      | `SSplitNav`（侧栏优先） |
| top-hybrid-header-first      | `horizontal-vertical`      | `SSplitNav`（头部优先） |
| vertical-hybrid-header-first | `horizontal-dual-vertical` | `SSplitNav`（混合）     |

### 5.3 路由与菜单一元模型

- 页面即文件：`src/pages/**` 自动生成路由表（`routing: { mode: 'virtual' }`，admin 无需生成文件；lite 分支同样使用）。
- `definePage({ requiresAuth: true, meta: { keepAlive, multiTab, pinned, ... } })` 编译期宏，零运行时开销。
- **动态路由**：dynamic 模式下后端菜单（menuType `menu|page`）→ `transformMenusToAutoRoutes` → `router.addRoute`；routeName/routePath 与页面路由表做一致性校验（启动断言，防漂移）。
- **标题**：菜单 `i18nKey` 单一来源；无菜单条目的静态页（异常页等）用 `definePage({ meta: { title } })` 兜底。此为对 v2 "meta.i18nKey 全局唯一来源"的简化统一。

### 5.4 请求层

```ts
// src/request/client.ts
import { createRequest } from '@soybeanjs/fetch';
import { toFlatTypedClient } from '@soybeanjs/fetch/openapi';
import type { paths } from '../../.ubean/openapi';

const request = createRequest(
  { baseURL: '/api' },
  {
    transform: response => response.data.data,
    isBackendSuccess: response => response.data.code === import.meta.env.VITE_SERVICE_SUCCESS_CODE,
    onRequest: config => {
      /* 注入 Bearer token */
    },
    onError: error => {
      /* 登出码 / 弹窗登出 / 过期刷新重放 / 错误去重 */
    }
  }
);

export const api = toFlatTypedClient<paths, '/api'>(request, '/api');
// 用法：const { data, error } = await api.get('/user/list', { params });
```

- 内核为 fetch（免 axios 依赖），上传进度用 `createUploadProgressAdapter`，文件下载用内置 `downloadFile`。
- `baseRequest` 承担：Bearer 注入、`{ code, message, data }` 解包、业务码分支（登出/弹窗登出/过期刷新重放）、错误去重。全部逻辑 ≤150 行。
- `paths` 类型来自 `.ubean/openapi.d.ts`（相对路径 import，见 §3.3）；`toFlatTypedClient<paths, '/api'>` 第二个泛型是 **API 前缀**，需与 `ubean.config.ts` 中路由挂载前缀一致（ubean-test 用 `/api`，unify 用 `/api/v1`）。
- 服务端进程内复用：`createInternalAdapter(c)` 注入 adapter，`internal.ts` 零网络直调 handler（unify/ubean-test 同款）。

### 5.5 鉴权流程

1. `POST /api/auth/login`（valibot 校验 + 验证码）→ 返回 `{ accessToken, refreshToken }` → `localStg` 存储。
2. 守卫首次进入：`GET /api/auth/user-info` + `GET /api/role/user` + `GET /api/menu/user` → 初始化路由/菜单/页签。
3. 登出：调 `POST /api/auth/logout`（拉黑 refreshToken）+ 前端 resetStore（修复 unify 未调后端的问题）。
4. 刷新链路：过期码 → 单飞 `refreshTokenPromise` → 重放队列 → 失败则登出。

## 6. 后端详细设计（仅 main 分支）

### 6.1 分层

```
src/routes/api/**     文件式 API 路由：defineHandler(defineHandlerMeta, describeRoute, validator('json', schema), handler)
src/server.ts         defineServer：全局 hooks（requestId、日志、错误映射）
src/middleware/       01.auth.ts：Bearer → verifyToken（黑名单+用户状态）→ 权限码匹配 → checkUserHasPermission
src/services/         纯函数/composable 业务层（每资源 *.service.ts）
src/db/               Drizzle schema（移植 unify 13 表：user/role/permission/api/menu/org/dict/dict-item + 4 关系表）+ 迁移 + seed
src/schema/           Valibot DTO（前后端源码直消费，不构建）
```

- 统一响应：`response` 中间件重写 `c.json` → `{ code:'0000', message, data }`；错误 `AppError` + error 中间件同构输出（含业务码：8888 登出 / 7777 弹窗登出 / 9999 过期，支撑前端演示页）。

- 服务端导入源（客户端不可用）：路由与处理器 / 应用入口 / cache / db / queue / cron / ws / sse / 中间件工厂 从 `ubean/server`；构建时工具（prerender / 平台预设 / 配置加载 / codegen 预设 / 扫描器 / Vite 插件本体）从 `ubean/build`；服务端 i18n（ALS `t()` / `createI18nMiddleware`）从 `ubean/i18n`。
- OpenAPI：dev 自动挂 `/_openapi.json` + `/_scalar`，替代 v2 "手写接口文档给后端同学"的痛点。
- 数据模型约定沿用 unify：UUID v7 字符串主键、`enabled: 'Y'|'N'|'D'` 软删、审计四字段。

## 7. 架子 + 第三方 UI 样式适配（要求 7）

### 7.1 架构原则：架子 100% 基于 `@vean/ui`，适配只做“样式对齐”

v3 的架子层（layout/menu/tabs/theme store/router/store/request）全部构建在 `@vean/ui` + `@vean/aria` 之上，**不存在"换 UI 库跑同一套架子"的转发层**。当业务页需要引入第三方组件时（naive-ui / element-plus / ant-design-vue——无论因 soybean-ui 组件缺口，还是因 v2 迁移用户存量代码），适配器的职责是：**让第三方组件适配 soybean-ui 的样式体系（颜色、圆角、字号、明暗等设计 token），保证同一页面视觉一致**。

### 7.2 适配器在独立仓库开发，不进本仓库

- 独立仓库（建议命名 `soybean-ui-adapters`）承载全部适配实现，soybean-admin 只保留两个对接点：
  1. **token 输出**：对接 `@vean/ui` 的 `useTheme()`（`ThemeContext`：`base`/`primary`/`radius`/`mode`/`theme` 计算属性与 `setRadius`/`setMode`/`savePreset`/`applyPreset` 等）与 `useThemeSettings()`（`state`/`setState`/`overrides`/`setOverride`/`resolved`/`commit`），必要时再叠 `@vean/theme` 的 `emitThemeCss()` 产物；
  2. **挂载约定**：用户在 `app.vue`（appRoot）按需注册适配器，如 `setupNaiveAdapter()`。

> ⚠️ **能力已具备，但契约仍是自定的**：`useThemeTokens()` 与 `soybean:theme-change` 这两个**名字**并不存在于 `@vean/ui` / `@vean/theme` / `@soybeanjs/ui`（2026-10 实测 `packages/ui/src`、`packages/theme/src` 均无命中）；但**等价能力已由库提供** —— `useTheme()` 暴露生效中的 `theme`（`ComputedRef<ThemeOptions>`）与 `base`/`primary`/`radius`/`mode` 等 `ShallowRef`，`useThemeSettings()` 提供 `resolved`/`overrides`/`setOverride`/`persist`。因此适配器应**对接这两个现成 composable**，而不是新造 `useThemeTokens()`；`soybean:theme-change` 式事件通知也应由适配器自己订阅 `watch(theme, …)` 实现。实现基础另可用 `@vean/theme` 的 `resolveThemeMap()` + `emitThemeCss(map)` + `./storage`（`createThemeWriter`/`readThemeEnvelope`/`writeThemeEnvelope`/`parseThemeOptions`）。对接签名需在适配器仓库开工前落定。

- 适配原理（按目标库主题机制选择）：
  - **naive-ui**：`ThemeSettings → GlobalThemeOverrides`（common.primaryColor/borderRadius/高度字号…），经 `NConfigProvider` 注入——即 v2 反向能力（naive overrides 跟 soybean token 走）；
  - **element-plus**：token → `--el-color-primary`（含 light-3/5/7/8/9、dark-2 派生梯度）、`--el-border-radius-base`、`--el-bg-color` 系列 CSS 变量直写；
  - **ant-design-vue**：token → `ConfigProvider :theme="{ token: { colorPrimary, borderRadius, colorBgContainer... }, algorithm: dark ? theme.darkAlgorithm : defaultAlgorithm }"`。
- 派生算法对齐：primary 梯度（hover/active/disabled）统一用 `@soybeanjs/colord` 按 soybean-ui 同一规则生成，避免三库各自派生导致色差。
- 交付形态：每库一个包（`@soybeanjs/adapter-naive` 等）+ 一个共享核心（token 映射表 + 订阅 `theme-change` 的 runtime），由适配器仓库独立发布、独立版本。

### 11.3 术语

- **一元数据模型**：菜单记录 = 导航条目 + 路由定义 + 页签标题来源（`App.Menu = MenuDTO + RouteKey 收窄`），源自 unify。
- **Vean / soybean-ui**：同一套代码的两个包名。本地/git 仓库与源码文档仍叫 **soybean-ui**（`@soybeanjs/ui`、`@soybeanjs/headless`），npm 发布时改名 **Vean**（`@vean/ui`、`@vean/aria`、`@vean/theme`、`@vean/unocss`）；本文档统一按 npm 名写 `@vean/*`，写代码时以 npm 名为准。
- **`S*` 组件**：Vean 的 styled 组件命名前缀（`SAppShell`/`STable`/`SForm`/`SConfigProvider`…）；无样式的 headless 原语不带前缀，位于 `@vean/aria`。
- **并行路由（`@slot`）**：ubean 用 `src/pages/<parent>/@<name>/` 实现“路由驱动的弹窗/抽屉”，父页用 `<SlotView name="<name>" />` 占位；区别于 Nuxt 的拦截路由（ubean 不做）。
- **样式适配（adapter）**：独立仓库实现，把 soybean-ui 的设计 token（颜色/圆角/明暗…）映射到 naive（themeOverrides）/ element（`--el-*` 变量）/ antd（ConfigProvider theme token），使第三方组件与 S\* 组件同页视觉一致。
- **契约源**：`src/schema/`（Valibot）为 DTO/校验唯一来源；OpenAPI 生成为类型客户端来源。
