# soybean-admin v3.0 实现方案

> 基于 ubean + vite-plus + soybean-ui 的全栈重构方案
>
> 状态：草案（供评审）
> 基线：soybean-admin v2.x（main = 脚手架内核，example = 全功能演示）
> 参考实现：soybean-unify（简约全栈参考）、ubean examples/ubean-test（全栈骨架参考）

---

## 1. 背景与目标

soybean-admin v2.x 是纯前端 SPA 模板：Vue 3 + Vite + Naive UI + Pinia + UnoCSS + elegant-router，后端能力完全依赖 Apifox 在线 mock 或用户自备服务。v3.0 的目标：

1. **整体技术栈升级为全栈框架**：以 [ubean](https://github.com/soybeanjs/ubean)（v0.4.1，Vue 全栈框架，Hono 内核）为基座，构建工具链切换为 vite-plus（`vp`），UI 层切换为 [VeanUI](https://veanui.com)（`@vean/ui` + `@vean/aria`）。
2. **能力对齐**：完整实现 v2.x（main + example）的全部能力，不丢"隐形能力"（见 §5.9）。
3. **简约优先**：以 soybean-unify 的简约实现为参考范式——单一契约源（`src/schema/` Valibot）、OpenAPI 类型化客户端、菜单驱动路由/页签/标题的一元数据模型、零自研布局、单包平铺工程结构。
4. **架子 + 样式适配**：用 soybean-ui 搭好完整架子（布局/导航/页签/主题）；第三方 UI 库（naive-ui / element-plus / ant-design-vue）的**样式适配器**（让第三方组件对齐 soybean-ui 的颜色、圆角等设计 token）在独立仓库开发，使 v2 各发行版平滑过渡到 v3。
5. **双版本交付**：
   - `main` 分支：**全栈版**（ubean 完整能力：文件路由 API + DB + 鉴权 + OpenAPI 类型共享）；
   - `lite` 分支（新分支承载）：**前端版**（仅 `@ubean/vue` 客户端内核 + 自定义后端，任意语言后端可接入）。

### 非目标

- 不实现 v2.x 从未存在过的能力（锁屏、cropper、ripple 等不在 example 基线内，不列入）。
- v3.0 首版不做 SSR/SSG（admin 面板模式官方推荐 `mode: 'fullstack' + ssr: false`）。
- 不做 naive-ui 等旧版组件级 1:1 转发适配（原因见 §7.1），适配器只做样式 token 对齐；适配器实现不进本仓库（§7.2）。

## 2. 技术选型总览

| 层              | v2.x 现状                                                         | v3.0 选型                                                                                                                                                              | 选型依据                                                                                               |
| --------------- | ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 应用框架        | 纯前端 SPA（Vite 手工装配）                                       | **ubean 0.4.x**（`mode: 'fullstack'`, `ssr: false`）                                                                                                                   | README 明确 admin panel 是 fullstack 模式的典型用例；client+server 双构建、无 SSR 开销                 |
| 构建/工程工具链 | Vite + ESLint + Prettier + Turbo（无）+ 手写脚本                  | **vite-plus（`vp`）**：dev/build/test/lint/fmt/pack 一体；catalog 中 `vite: npm:@voidzero-dev/vite-plus-core`                                                          | ubean 深度绑定 vite-plus；soybean-unify 已验证该工作区编排（`vp check --fix` staged、oxlint/oxfmt）    |
| 路由            | elegant-router 插件生成 + 手写守卫                                | **ubean 文件式页面路由**（`src/pages/**` + `definePage` 宏 + `.ubean/routes.d.ts` 类型化路径），守卫注入 `defineApp({ router: { setup } })`                            | 与 elegant-router 同族的文件约定，且额外获得动态段 matcher、keep-alive、复用路由、并行/拦截路由        |
| 状态管理        | Pinia + `@sa/*` 私有包                                            | **Pinia**（经 `@ubean/integrations/pinia`，`pinia: true`）                                                                                                             | 框架不内置 store；unify 验证 6 个 store 足够                                                           |
| UI 组件         | Naive UI（架构级耦合：NConfigProvider/四大 Provider/TableColumn） | **SoybeanUI 0.30+**（`@vean/ui` styled + `@vean/aria`）+ `@vean/theme` + `@vean/unocss`                                                                                | `SAppShell` 一个组件承接 v2 全部 6 种布局模式与菜单形态（见 §5.2）；ubean `ui: true` 自动接 UiResolver |
| HTTP 客户端     | `@sa/axios`（axios 内核 flat request）                            | **`@soybeanjs/fetch`**（`createRequest`/`toFlatRequest` + `/openapi` 子路径 `createTypedClient`/`toFlatTypedClient`，含 `createUploadProgressAdapter`/`downloadFile`） | ubean 官方指定客户端（`examples/ubean-test/src/request/client.ts` 即此用法）；fetch 内核免 axios 依赖  |
| 工程 CLI        | `@sa/scripts`（`sa git-commit`/`release`/`changelog`/`cleanup`）  | **`@soybeanjs/cli`**（1.8.x，bin `soy`：`git-commit`/`git-commit-verify`/`changelog`/`release`/`cleanup`/`ncu`/`config`）                                              | 官方维护通用 CLI，能力覆盖 `@sa/scripts`；`gen-route` 由文件式路由天然替代                             |
| 后端            | Apifox 在线 mock（无真实服务）                                    | **ubean 后端**：`src/routes/api/**` 文件路由（Hono handler 链）+ valibot 校验 + `@ubean/server` 原语（db/cache/session…）                                              | unify 的 server（Hono + Drizzle + RBAC）即为该形态的手写版，ubean 将其框架化                           |
| 数据层          | 无                                                                | **Drizzle ORM + db0 connector**（dev 默认 SQLite/内存，prod 可切 Postgres）+ drizzle 迁移                                                                              | `defineDatabase`/`useDatabase` 原语；unify 的 13 表 schema 可直接移植                                  |
| 鉴权            | mock 假登录 + 前端 roles 过滤                                     | **JWT 双 token + Redis/内存黑名单**（unify 方案）或 `@ubean/auth`（Better Auth）；RBAC 权限码 `api:${method}:${template}`                                              | 见 §6.4；`@ubean/auth` 成熟度待观察，首版建议沿用 unify 自研 JWT 方案以可控                            |
| 类型共享        | 手写 `typings/api/*.d.ts`                                         | **单一契约源**：`src/schema/`（Valibot，前后端源码直消费）+ OpenAPI codegen（`.ubean/openapi.d.ts`）→ `toFlatTypedClient<paths>`                                       | Hono 路由 → `/_openapi.json` → openapi-typescript 闭环，ubean 内置；应用单包化后 schema 无需独立包     |
| 主题            | naive themeOverrides + 4 个 JSON 预设                             | **`@vean/theme`**（`createTheme` CSS 变量引擎）+ `SConfigProvider`/`SThemeCustomizer`                                                                                  | shadcn 风格全量语义 token，light/dark 双份，`SThemeCustomizer` 即现成主题抽屉                          |
| i18n            | vue-i18n 手工装配                                                 | **`@ubean/i18n`**（vue-i18n 11 + 约束前缀语言路由 + `src/locales/` 扫描）                                                                                              | 配置化（`i18n: { locales, defaultLocale }`），`.ubean/i18n.d.ts` 类型生成                              |
| 图标            | iconify + unplugin-icons + svg-icons 三套                         | **`@ubean/icon`**（`icon: true`，Iconify）+ `SIcon`（`IconValue`）+ 本地 svg 约定                                                                                      | soybean-ui 数据模型（menu/table 的 `icon` 字段）直接吃 iconify 字符串                                  |

**版本风险声明**：ubean 当前 0.4.1、README 标注"不可生产"，0.3→0.4 刚做过入口大重构。v3.0 发布节奏必须与 ubean 版本锁定策略绑定（见 §10）。

## 3. 仓库与工程结构

### 3.1 项目结构（main 分支 = 全栈版，单包平铺）

v3 不再使用 monorepo：应用直接落在仓库根目录（等价于把 v2 设想中 `apps/admin/` 的内容平铺），全栈应用的天然属性（前端 + API + 数据库同仓同进程）使 workspace 分层失去意义。

```
soybean-admin/
├── ubean.config.ts               # defineConfig: mode/preset/i18n/ui/icon/pinia/devtools/routing
├── vite.config.ts                # import { defineConfig } from 'vite-plus'; plugins: [ubeanPlugin()]
├── .env / .env.prod              # 精简后的 env 变量（见 §5.10）
├── package.json                  # 单包：scripts 用 vp + soy（@soybeanjs/cli）
├── src/
│   ├── pages/                    # 文件式页面路由（替代 v2 src/views）
│   │   ├── (builtin)/            #   login / 403 / 404 / 500 / iframe-page
│   │   ├── home/                 #   dashboard
│   │   ├── manage/               #   user / role / menu / permission / dict ...
│   │   ├── function/             #   功能演示（tab / multi-tab / request / access-control ...）
│   │   ├── multi-menu/           #   多级菜单演示
│   │   ├── plugin/               #   插件演示（editor / excel / pdf / charts ...）
│   │   └── about/
│   ├── routes/                   # API 路由（替代 Apifox mock）
│   │   └── api/
│   │       ├── auth/             #   login / refresh / logout / user-info
│   │       ├── menu/             #   public / user / exist-path
│   │       └── user/ role/ permission/ org/ dict/ ...
│   ├── schema/                   # 前后端共享 Valibot schema + DTO 类型（原 unify packages/schema 下沉至此）
│   ├── layouts/                  # default.vue（= SAppShell 壳）/ blank.vue
│   ├── middleware/               # 服务端鉴权中间件（01.auth.ts）
│   ├── services/                 # 服务端业务层（每资源 *.service.ts）
│   ├── db/                       # Drizzle schema + 迁移 + seed
│   ├── locales/                  # zh-CN.json / en-US.json
│   ├── components/               # 全局小组件
│   ├── composables/              # useTableOperate / useAuth / useCaptcha ...
│   ├── constants/                # 挂载点 ID、正则、i18n key 映射
│   ├── directives/               # v-auth（按钮级权限）等
│   ├── shared/                   # storage / table / request 适配
│   ├── store/                    # pinia: app / auth / menu / route / tab / theme
│   ├── styles/                   # 全局 css（走 @vean/unocss）
│   ├── theme/                    # 主题预设 JSON（shadcn-theme 兼容）
│   ├── request/                  # typed client（client.ts / internal.ts）
│   ├── typings/                  # 环境/全局类型补充
│   ├── server.ts                 # defineServer（全局 hooks）
│   ├── app.ts                    # defineApp（router.setup 守卫、appRoot）
│   └── app.vue                   # appRoot 包装：SConfigProvider + Provider 挂载
├── scripts/                      # 辅助脚本：openapi/seed/remove-i18n（dev/build 由 vp + ubean CLI 承担）
├── docs/                         # v3.md（本文档）等
└── .github/workflows/            # lint + typecheck + build + release
```

要点：

- **删除 v2 的 `packages/` 私有包体系**（`@sa/axios`、`@sa/materials`、`@sa/hooks`、`@sa/color`、`@sa/scripts`、`@sa/uno-preset`、`@sa/alova`、`@sa/ofetch`）与根 `pnpm-workspace.yaml`：其职责分别由 `@soybeanjs/fetch`、soybean-ui、`@soybeanjs/utils`、`@vean/theme`、`@soybeanjs/cli`、`vp` 承担，全部以已发布 npm 包消费，仓库内不再维护本地包。
- **schema 下沉 `src/schema/`**：全栈应用前后端同进程、同 tsconfig，Valibot schema 直接以相对路径 import（`#/schema/auth`），无需 workspace 包；DTO 类型即 schema 推导类型，单一契约源不变。
- **第三方 UI 样式适配不放本仓库**：由独立仓库开发（见 §7.2），本项目只保留对接约定。
- **mock 服务退役**：`src/service/api/*` 手写 API 层与 Apifox mock 全部删除，接口由 `src/routes/api/**` 真实实现，dev 即跑真后端（同进程，Vite middlewareMode + Hono）。
- **v2 `src/views` → `src/pages`**：文件约定基本同构（`[id].vue` 动态段、`(group)` 路由组、`_builtin` → `(builtin)`），迁移以目录重命名 + meta 改写为主。
- 路径别名统一 `#/` → `src/`（vite-plus `tsconfigPaths` + ubean 默认约定）。

### 3.2 双版本分支策略（要求 8）

|          | `main`（全栈版，默认）                                                | `lite`（前端版，新分支）                                                                                                                                                                                                        |
| -------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 框架入口 | `ubean`（`ubean/client`、`ubean/server` 全量）                        | 仅 `@ubean/vue` + `@ubean/client`（或纯 `@ubean/vue` 内核，参照 `examples/client-only-spa`）                                                                                                                                    |
| 后端     | `src/routes/api/**` + `@ubean/server` 原语 + Drizzle                  | **无后端代码**；`src/request/` 指向用户自备 API（任意语言），契约用 OpenAPI 文档 + `openapi-typescript` 手工生成                                                                                                                |
| 构建     | `ubean dev/build`（client+server 双构建）                             | `vp build`（纯 Vite SPA），`vite.config.ts` 用 `ubeanVueVite()`                                                                                                                                                                 |
| 路由     | 文件式 `src/pages` + virtual routes                                   | 同样文件式（`@ubean/vue` 是多目录页面路由唯一所有者），无 loader/SSR 数据层                                                                                                                                                     |
| 鉴权     | JWT 双 token + RBAC 中间件                                            | 前端流程保留（登录页/守卫/token 存储/权限过滤），接口路径与响应码 env 可配                                                                                                                                                      |
| mock     | 不需要（真后端）                                                      | 可选保留轻量本地 mock（`routeRules.proxy` 或 MSW），默认提供 unify 风格 `docs/api-contract.md` 接口契约说明                                                                                                                     |
| 共享代码 | `src/schema`、`src/store`、`src/layouts`、`src/components` 等绝大部分 | 与 main 尽量保持目录与代码一致，差异集中在：`ubean.config.ts`、`vite.config.ts`、`src/routes/`+`src/services/`+`src/db/`（删除）、`src/server.ts`（删除）、`src/request/`（改 baseURL 来源）、`src/schema/`（保留但仅前端消费） |

**同步机制**：`lite` 分支定期从 `main` rebase/merge，冲突面控制在上述差异点（集中在 5 个文件/目录）。CI 对两分支都跑 typecheck + build。文档站分别说明两种起步方式：`pnpm create` 模板对应 main；lite 作为"接入自定义后端"的官方示例。

### 4.2 路由与权限

| v2.x 能力                                            | v3.0 实现                                                                                                                                                                                                                | 状态                                              |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------- |

### 5.1 应用入口与生命周期

// src/app.ts

export default defineApp({

`app.vue`（appRoot）：`SConfigProvider`（theme/persistTheme/dir/locale）+ Toast/Dialog Provider 挂载 + 全局水印 `SWatermark`。

### 5.2 布局架子（layouts/default.vue）

```vue
<script setup lang="ts">
import { SAppShell } from '@vean/ui';

const active = ref('');
// items：菜单树（AppShellMenuItem[]，唯一数据入口；面包屑/高亮路径由 shell 派生）
</script>
<template>
  <SAppShell
    v-model="active"
    v-model:tab-value="tabStore.activeTab"
    mode="dual-vertical"
    :items="menuStore.items"
    :tabs="tabStore.tabs"
    expand-strategy="keep"
    @tab-click="tabStore.switchTab"
    @tab-close="tabStore.removeTab"
  >
    <template #logo><AppLogo /></template>
    <template #headerStart>
      <!-- 折叠触发按钮位置由 shell 按一级菜单位置决定，无需手摆 -->
    </template>
    <template #headerCenter><GlobalSearch /></template>
    <template #headerEnd>
      <UserAvatar />
      <ThemeModeSwitch />
    </template>
    <template #default><RouterView /></template>
    <template #footer v-if="footerVisible"><LayoutFooter /></template>
  </SAppShell>
</template>
```

要点：

- `mode` 承接 v2 全部 6 种布局：`sidebar`（原 vertical / vertical-mix 的侧栏形态）、`top`（原 horizontal）、`dual-vertical`（原 vertical-mix）、`vertical-horizontal`（原 top-hybrid-sidebar-first）、`horizontal-vertical`（原 top-hybrid-header-first）、`horizontal-dual-vertical`（原 vertical-hybrid-header-first）。模式名描述**菜单形态**而非方向：一级菜单垂直 = 全高侧栏，一级水平 = 顶栏；`orientation` 等布局朝向由 shell 从 mode **派生**（相对旧 `SLayout` 直填 props 是反转的），应用层不再手写。
- **一棵菜单树喂所有渲染器**：`items: AppShellMenuItem[]` 是唯一菜单数据入口，sidebar/top 渲染 `STreeMenu`/`STreeNav`，4 种 split 模式渲染 `SSplitNav`，无需按模式切换组件。
- `breadcrumbs` 默认由 `items` + 激活值**自动派生**（原 menu store 派生逻辑内化），传入才覆盖；`expandStrategy: 'selected' | 'keep'` 控制折叠后展开策略（top 模式无此项；`menuProps.tree/split` 优先级更高）。
- 品牌/标题仅经 `#logo`/`#title` 插槽注入，`logoPlacement: 'auto' | 'sidebar' | 'sidebar-bottom' | 'header'` 控制落位（`sidebar-bottom` 仅 sidebar/dual-vertical 生效）；折叠触发按钮位置跟随一级菜单位置，由 shell 统一安排。
- 移动端恒以 `sidebar` 骨架渲染**全量菜单树抽屉**（767.9px 断点；props 保留宿主传值），`v-model:mobileOpen` 受控。
- 主题/布局配置映射：theme store → `layoutProps` 转发内部 `SLayout`（shell 自己持有 open/orientation/sidebarVisible/isMobile/pxToRem，应用层只喂配置面）；样式三层 `ui` / `layoutUi` / `menuUi`（tree/split/treeNav）。
- 与路由无关：纯数据入（items/tabs/breadcrumbs）+ 事件出（`update:open` / `update:mobileOpen` / `update:modelValue` / `select` / `open` / `update:tabValue` / `update:tabs` / `tabClick` / `tabClose`），路由联动留在 route/menu store。

v2 layout.mode → SAppShell mode 映射表：

| v2 layout.mode               | SAppShell `mode`           | 渲染器                  |
| ---------------------------- | -------------------------- | ----------------------- |
| vertical                     | `sidebar`                  | `STreeMenu`（单栏）     |
| vertical-mix                 | `dual-vertical`            | `SSplitNav`（双栏）     |
| horizontal                   | `top`                      | `STreeNav`（横排）      |
| top-hybrid-sidebar-first     | `vertical-horizontal`      | `SSplitNav`（侧栏优先） |
| top-hybrid-header-first      | `horizontal-vertical`      | `SSplitNav`（头部优先） |
| vertical-hybrid-header-first | `horizontal-dual-vertical` | `SSplitNav`（混合）     |

### 5.3 路由与菜单一元模型

- 页面即文件：`src/pages/**` 自动生成路由表（`routing: { mode: 'virtual' }`，admin 无需生成文件；lite 分支同样使用）。
- `definePage({ requiresAuth: true, meta: { keepAlive, multiTab, pinned, ... } })` 编译期宏，零运行时开销。
- **动态路由**：dynamic 模式下后端菜单（menuType `menu|page`）→ `transformMenusToAutoRoutes` → `router.addRoute`；routeName/routePath 与页面路由表做一致性校验（启动断言，防漂移）。
- **标题**：菜单 `i18nKey` 单一来源；无菜单条目的静态页（异常页等）用 `definePage({ meta: { title } })` 兜底。此为对 v2 "meta.i18nKey 全局唯一来源"的简化统一。

### 5.4 请求层

```ts
// src/request/client.ts
import { createRequest } from '@soybeanjs/fetch';
import { toFlatTypedClient } from '@soybeanjs/fetch/openapi';
import type { paths } from '../../.ubean/openapi';

const request = createRequest(
  { baseURL: '/api' },
  {
    transform: response => response.data.data,
    isBackendSuccess: response => response.data.code === import.meta.env.VITE_SERVICE_SUCCESS_CODE,
    onRequest: config => {
      /* 注入 Bearer token */
    },
    onError: error => {
      /* 登出码 / 弹窗登出 / 过期刷新重放 / 错误去重 */
    }
  }
);

export const api = toFlatTypedClient<paths, '/api'>(request, '/api');
// 用法：const { data, error } = await api.get('/user/list', { params });
```

- 内核为 fetch（免 axios 依赖），上传进度用 `createUploadProgressAdapter`，文件下载用内置 `downloadFile`。
- `baseRequest` 承担：Bearer 注入、`{ code, message, data }` 解包、业务码分支（登出/弹窗登出/过期刷新重放）、错误去重。全部逻辑 ≤150 行。
- 服务端进程内复用：`createInternalAdapter(c)` 注入 adapter，`internal.ts` 零网络直调 handler（unify/ubean-test 同款）。

### 5.5 鉴权流程

1. `POST /api/auth/login`（valibot 校验 + 验证码）→ 返回 `{ accessToken, refreshToken }` → `localStg` 存储。
2. 守卫首次进入：`GET /api/auth/user-info` + `GET /api/role/user` + `GET /api/menu/user` → 初始化路由/菜单/页签。
3. 登出：调 `POST /api/auth/logout`（拉黑 refreshToken）+ 前端 resetStore（修复 unify 未调后端的问题）。
4. 刷新链路：过期码 → 单飞 `refreshTokenPromise` → 重放队列 → 失败则登出。

### 5.6 主题系统

## 6. 后端详细设计（仅 main 分支）

### 6.1 分层

```
src/routes/api/**     文件式 API 路由：defineHandler(defineHandlerMeta, describeRoute, validator('json', schema), handler)
src/server.ts         defineServer：全局 hooks（requestId、日志、错误映射）
src/middleware/       01.auth.ts：Bearer → verifyToken（黑名单+用户状态）→ 权限码匹配 → checkUserHasPermission
src/services/         纯函数/composable 业务层（每资源 *.service.ts）
src/db/               Drizzle schema（移植 unify 13 表：user/role/permission/api/menu/org/dict/dict-item + 4 关系表）+ 迁移 + seed
src/schema/           Valibot DTO（前后端源码直消费，不构建）
```

- 统一响应：`response` 中间件重写 `c.json` → `{ code:'0000', message, data }`；错误 `AppError` + error 中间件同构输出（含业务码：8888 登出 / 7777 弹窗登出 / 9999 过期，支撑前端演示页）。
- OpenAPI：dev 自动挂 `/_openapi.json` + `/_scalar`，替代 v2 "手写接口文档给后端同学"的痛点。
- 数据模型约定沿用 unify：UUID v7 字符串主键、`enabled: 'Y'|'N'|'D'` 软删、审计四字段。

### 6.2 数据库与驱动

- dev：`defineDatabase` 默认 SQLite 文件（better-sqlite3 connector），开箱跑通 + seed 演示数据。
- prod：Postgres（postgres-js）；cloudflare 适配版（D1）作为可选示例目录（参考 unify `apps/cloudflare`，v3.2 再评估）。
- 风险：ubean DB 原语默认内存实现，必须显式接线 db0 connector 并在文档强调（roadmap 自述风险）。

### 6.3 接口清单（对齐 v2 mock + unify）

| 模块                                      | 端点                                                                                                                                                    |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| auth                                      | `POST /login`（pwd/captcha 双类型）、`POST /register`、`POST /token/refresh`、`POST /logout`、`GET /user-info`、`POST /error`（演示码）、`GET /captcha` |
| menu                                      | `GET /public`、`GET /user`、`POST /exist-path`、CRUD + tree                                                                                             |
| role                                      | CRUD + `GET /user`（角色码）+ 菜单/按钮权限分配                                                                                                         |
| user                                      | CRUD + 状态 + 分配角色                                                                                                                                  |
| permission / api / org / dict / dict-item | CRUD（unify 8 套范式）                                                                                                                                  |

### 6.4 鉴权方案取舍

- **首版**：unify 式自研 JWT（hono/jwt + bcryptjs + 黑名单经 `useCacheStore`，dev 内存 / prod Redis driver）——行为完全可控，与 v2 业务码语义无缝。
- **演进**：`@ubean/auth`（Better Auth）作为 v3.x 可选模块评估切换（session/多 provider 能力更强），通过 `defineHandlerMeta({ requiresAuth })` + `useAuth()` 前端体验统一，切换成本收敛在 auth 模块。

### 6.5 服务端能力利用（ubean 差异化价值）

`defineQueue`（导出任务异步化）、`defineScheduled`（字典缓存刷新）、`defineWebSocket`/`createSSEStream`（通知中心演示页）、`useRateLimit`（登录防爆破）、`useCacheStore`（验证码/字典缓存）、`routeRules`（dev 代理、prod CDN headers）。这些作为 v3.1+ 增值演示，不进首版关键路径。

## 7. 架子 + 第三方 UI 样式适配（要求 7）

### 7.1 架构原则：架子 100% 基于 soybean-ui，适配只做"样式对齐"

v3 的架子层（layout/menu/tabs/theme store/router/store/request）全部构建在 `@vean/ui` + `@vean/aria` 之上，**不存在"换 UI 库跑同一套架子"的转发层**。当业务页需要引入第三方组件时（naive-ui / element-plus / ant-design-vue——无论因 soybean-ui 组件缺口，还是因 v2 迁移用户存量代码），适配器的职责是：**让第三方组件适配 soybean-ui 的样式体系（颜色、圆角、字号、明暗等设计 token），保证同一页面视觉一致**。

### 7.2 适配器在独立仓库开发，不进本仓库

- 独立仓库（建议命名 `soybean-ui-adapters`）承载全部适配实现，soybean-admin 只保留两个对接点：
  1. **token 输出**：theme store 将生效的 `@vean/theme` 变量（`--primary`/`--radius`/`--background`/`--sidebar-*`…，light/dark 双份）以结构化对象暴露（`useThemeTokens()`），并派发 `soybean:theme-change` 事件；
  2. **挂载约定**：用户在 `app.vue`（appRoot）按需注册适配器，如 `setupNaiveAdapter()`。
- 适配原理（按目标库主题机制选择）：
  - **naive-ui**：`ThemeSettings → GlobalThemeOverrides`（common.primaryColor/borderRadius/高度字号…），经 `NConfigProvider` 注入——即 v2 反向能力（naive overrides 跟 soybean token 走）；
  - **element-plus**：token → `--el-color-primary`（含 light-3/5/7/8/9、dark-2 派生梯度）、`--el-border-radius-base`、`--el-bg-color` 系列 CSS 变量直写；
  - **ant-design-vue**：token → `ConfigProvider :theme="{ token: { colorPrimary, borderRadius, colorBgContainer... }, algorithm: dark ? theme.darkAlgorithm : defaultAlgorithm }"`。
- 派生算法对齐：primary 梯度（hover/active/disabled）统一用 `@soybeanjs/colord` 按 soybean-ui 同一规则生成，避免三库各自派生导致色差。
- 交付形态：每库一个包（`@soybeanjs/adapter-naive` 等）+ 一个共享核心（token 映射表 + 订阅 `theme-change` 的 runtime），由适配器仓库独立发布、独立版本。

### 7.3 soybean-ui 当前缺口与对策

| 缺口（docs/roadmap P0/P1）                                                                        | v3 对策                                                                                                                                                                                 |
| ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Upload                                                                                            | 优先自建（`@vean/aria` 无该原语）：文件列表 + 拖拽 + 进度，样式用 S\* 拼装，上传走 `@soybeanjs/fetch` 的 `createUploadProgressAdapter`；若直接用目标库 Upload，则由 §7.2 适配器对齐样式 |
| Descriptions / TreeSelect / Transfer / Timeline / Statistic / Result / Typography / Image / Space | 应用层小组件先行（`components/custom/`），同步向 soybean-ui 提 issue/PR，成熟后替换                                                                                                     |
| 表格虚拟滚动已有（virtualizer）；图表仅 4 件                                                      | dashboard 图表继续用 echarts + `@soybeanjs/chart` container                                                                                                                             |

### 7.4 v2 naive/element/antd 版用户迁移路径

1. `pnpm create soybean-admin@v3`（全栈版）或 clone `lite` 分支；
2. 业务页从 `views/` 迁到 `pages/`，`useNaiveTable` → `usePaginatedTable`（列模型字段映射表随迁移文档提供）；
3. 存量第三方组件页暂不改写 → 安装对应适配器包（如 `@soybeanjs/adapter-naive`），第三方组件即自动跟随 soybean-ui 主题（含暗色切换与自定义主色/圆角），页面视觉一致；
4. 随 soybean-ui 组件覆盖度提升逐页替换为 S\* 组件，最终移除适配器——**一套架子渐进收敛**，替代 v2 时代"每个 UI 库 fork 一个仓库"（soybean-admin-element-plus 等）的维护模式。

## 8. lite 分支（@ubean/vue 前端版）详细设计（要求 8）

基于 `examples/client-only-spa` 形态：

```ts
// vite.config.ts
import { defineConfig } from 'vite-plus';
import { ubeanVueVite } from '@ubean/vue/vite';
export default defineConfig({ plugins: [ubeanVueVite({ markdown: false, head: true })] });

// main.ts
import { createApp } from 'vue';
import { ubeanVue } from '@ubean/vue';
import routes from 'virtual:ubean-vue-routes';
createApp(App).use(ubeanVue, { routes }).mount('#app');
```

- 保留：文件式路由 + `definePage`、动态段 matcher、keep-alive、页面过渡、`<Link>/<PageView>`。
- 移除：`src/routes/`、`src/server.ts`、`ubean.config.ts`、loader/usePage 数据层、`@ubean/i18n`（改手工 vue-i18n 装配，与 v2 一致）、SSR 相关一切。
- 请求层：`toFlatTypedClient<paths>` 的 `paths` 来自用户 `openapi-typescript <用户后端 openapi.json>` 生成脚本（`pnpm gen:api`），文档提供 Java/Go/Python/Node 各后端的契约示例。
- 鉴权：前端流程同 main（守卫/存储/权限过滤），登录接口路径 env 可配（`VITE_API_LOGIN_PATH` 等），兼容非标准响应码。
- 维护约定：lite 不引入框架未提供的"伪全栈"能力；两分支差异清单固化在 `docs/lite-delta.md`，CI 校验 main→lite merge 只触碰 5 个差异文件。
